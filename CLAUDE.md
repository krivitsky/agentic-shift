## Stack
- Plain static site: HTML + CSS in `public/`, **no dependencies, no deploy-time build** — no `package.json`, nothing to install.
- Production serves `public/` statically (`vercel.json`); Vercel resolves clean URLs (`/munich`) natively. Local dev: `npx serve public` → http://localhost:3000. Keep it dependency-free — a local server that adds routes Vercel doesn't have creates dev/prod drift (that's how a `/new` redirect lived in dev while prod 404'd for months).
- **The manifesto pages are generated** (zero-dep Node generator) — see §Manifesto i18n. Generated HTML is committed, so the *deploy* still runs no build; the generator is only for editing content.

## Deploy
- Vercel, auto-deploys on push to `main`. Commit + push only when asked.
- **When the user says "commit"/"push": commit, push, then run the full deploy check below and report it.** Don't stop at the first status line — report **all** statuses and check-runs, then confirm the change is actually live.
  1. **Poll combined status** until terminal (`pending` → `success`/`failure`/`error`):
     `gh api repos/krivitsky/agentic-shift/commits/<sha>/status --jq '.state, (.statuses[] | "  \(.state)  \(.context)  \(.target_url)")'`
     Report the combined `state` **and every** status context (there's usually one, `Vercel`, but list all — a second context can be red while the first is green).
  2. **List check-runs** (GitHub Actions, if any):
     `gh api repos/krivitsky/agentic-shift/commits/<sha>/check-runs --jq '.check_runs[] | "  \(.name): \(.status)/\(.conclusion)"'`
     Empty output = no Actions configured (currently the case) — say so rather than silently skipping.
  3. **Verify live, don't trust green.** Vercel `success` means the build finished, not that the CDN serves it. `curl` the affected public URL(s) and confirm a `200` **and** an expected content marker (e.g. the new string/CSS value). Only after that is the deploy "done".
- Report the final combined state, each status/check line, the Vercel `target_url`, and the live-verify result.

## Versions: which page is the homepage
- **One setting: `manifesto/live.json` → `"live": "v3"`.** `node manifesto/build.js` takes `public/<live>/index.html` and writes it to `public/index.html`, swapping only the head: robots → `index, follow`; canonical, `og:url` and the JSON-LD `url` `https://agenticshift.org/vN` → `https://agenticshift.org/`; the `<!-- LIVE:HREFLANG -->` and `<!-- LIVE:ANALYTICS -->` lines → the hreflang alternates and the Google tag. Body, styles, scripts and asset paths stay the version's own. The build stops with an error if the page lacks any of those hooks.
- **To change the live version** ("make v4 live"): set `"live": "v4"` in `manifesto/live.json` → `node manifesto/build.js` → commit → push → verify (§Deploy). `/v4` itself stays noindex.
- **To edit a version:** edit `public/vN/index.html` by hand; it is the source. **If that version is live, re-run the build before committing.** There is no deploy-time build, so `/` stays stale until you do. That is the one way this setup breaks.
- **Why not a Vercel rewrite:** it would serve the version's noindex head at `/`, and `npx serve public` would have no homepage locally.
- **A new version page needs:** exactly one `<meta name="robots" content="noindex, nofollow">`; canonical, `og:url` and JSON-LD `url` absolute on `https://agenticshift.org/vN`; the two `LIVE:` lines in its head; absolute `/vN/…` asset paths with the files copied into its folder; its own language switcher. Keep it out of `sitemap()`.
- **What does not follow the live version:** `en.json` and everything built from it still carry the **v3** text: the 15 translations, the root `.md` downloads, `llms.txt`, the README manifesto block, and the English glosses on translated pages. Making v4 live without moving `en.json` and the translations to v4 leaves all of those on v3.

## Manifesto i18n
- **One source per language since 2026-10-26.** The 15 translated pages render from `content/<lang>.json` + `template.html` (the slider design). The English homepage is the live version page (§Versions); `en.json` still drives the English `.md`, llms.txt, the README and the glosses. The pre-slider translation files are in git history before that date.
- **Pipeline lives in `manifesto/`:** `content/*.json` (one per language, content only), `template.html` (markup, once), `build.js` (zero-dep Node generator). Languages: en (canonical) · de · nl · fr · it · es · pt · pl · cs · da · no · sv · uk · ru · zh · ja.
- **Edit content → `node manifesto/build.js` → generates** `public/index.html` (from the live version page, §Versions), `public/<lang>/index.html`, `public/<lang>/agentic-shift-<lang>.md` (downloadable per-language Markdown — locale in the filename so mobile Safari saves it right even when it ignores the `download` attr; linked from the language switcher via a Markdown-mark icon + the current lang code in brackets, e.g. `[DE]`), `public/sitemap.xml`, and the `MANIFESTO`-marked regions of `README.md` + `public/llms.txt`. Generated files carry a `GENERATED … do not edit` banner (or `MANIFESTO` markers). **Never hand-edit them** — the next build overwrites.
- **`en.json` is canonical — every change to it propagates to all 15 translations in the same session.** Adding or editing a lede paragraph, shift, Q&A, or meta field on the homepage is **not done** until each `content/<lang>.json` carries it; a partly-translated set means those pages silently serve an older manifesto. `build.js` enforces this: it prints `✗ TRANSLATION DRIFT` naming each language and exactly what it lacks, and **exits 1** (files are still written, so you can iterate). A green run ends with `✓ all 15 translations match en.json` — never commit a red one. (Added 2026-07-30, after the `/community` Q&A ran English-only for weeks.)
- **Page shape (v4, 2026-10-26):** `hero` (headlineLead/headlineTail stay "Agentic"/"Shift" untranslated — the green bar is sized to "Agentic" — plus subtitle) · `shiftHead` + `shiftIntro[]` (2 paragraphs) · `ownHead` + `shifts[]` (6 slider rows: `from`, `to`, `note`) · `useHead` + `use[]` (2) · `qaHead` + `qa[]` (1) · `foot.by` · `ui` (Markdown download label, theme-toggle labels). `meta.title`/`ogTitle` = "Agentic Shift — thoughtful AI adoption" (Alexey, 2026-10-27), the tail localized per language and "Agentic Shift" never translated; `og:site_name` stays plain "Agentic Shift"; descriptions = the subtitle. **No numbers on the shifts** — they are a set, not a sequence; how far to take each is the organization's call. `parityDrift()` checks every key, exact array lengths, and that no `from`/`to`/`note`/`q`/`a`/paragraph is blank. Translated rows show the English `from`/`to` under each term (`.gloss`, sourced from `en.json`).
- **Page-scoped CSS lives in `manifesto/template.html`**, not in `shift.css` — that way all 15 translated pages inherit it. The version pages carry their own copies, so a homepage design change means editing the live version page too. Anything shared with `/munich` or `/v1` `/v12` belongs in `shift.css` instead.
- **New/re-done translations get a back-translation pass:** render the language back to literal English and diff against `en.json` before shipping. First-pass drafts reliably flatten precise words — the Czech pass lost *one-off*, *well-engineered*, *mentoring*, *empathize*, *reinvention*, and *acknowledge*. Log native corrections in `manifesto/reviews/<lang>.md`.
- Each translated page shows the localized `from → to` pair with the **canonical English pair beneath it**, sourced from `en.json` at build time (can't drift). English page shows no gloss.
- **Adding a language:** add `content/<lang>.json`, then its entry in `ALL_LANGS`/`OG_LOCALE`/`LANGBAR_LABEL` in `build.js`, and run the build — switcher, hreflang, and sitemap update automatically. A language with no JSON is simply absent (not half-rendered).
- **Language code ≠ URL path.** The filename/`lang` key is the **ISO 639-1 code** and drives `lang=`, `hreflang=`, and the `[XX]` Markdown badge — never a country code there (`hreflang="cz"` is invalid and Google drops the alternate). The **`dir` field is the public path** and is free-form: Czech is `cs` internally but ships at **`/cz/`**, the code people recognise. `build.js` derives the output directory from `dir`, so the two can differ per language.
- **Native-reviewer corrections:** translations are first-pass drafts except where a native has reviewed. Their exact corrections are logged in `manifesto/reviews/<lang>.md` — **re-apply these if a language is ever re-translated**, and record in that file what carried over and what lapsed. So far: `pt` (the `proxies → utilizadores` wording carried into the 2026-08-09 rewrite; the `guardrails` correction lapsed with the shift it belonged to).
